How I work

Four habits that show up in every project.

They are the difference between a demo that works once and an agent a team can rely on.

Evidence before claims

I report what I measured, on what data, and what the number does not show. Where the data is invented, I say so on the page.

Evaluate before I edit the rules

A change that raises the pass rate can still break something. I read the regressions first, and every incident becomes a test case.

Ask before acting

Dry-run, approval tied to the exact plan, an audit trail, and undo. Agents that write to team systems need all four.

How I train my agent

My own agent has learned from about 130 corrections.

I use a personal AI analyst every day. It doesn't improve because I write a longer prompt. It improves because every correction goes through a quality bar, and only the ones that generalize become rules.

~130rules in one instruction file, each with a reason and an example
14sections, from approval policy to data-access patterns
~3 moof daily use, one correction at a time
Try the triage yourself Read the method
  • Verify a metric against the source's definition before encoding it.A rule written from a verbal description would have subtracted a quantity twice. The live agent caught it by reading the data model's glossary.
  • Don't batch an edit and the command that tests it.Independent tool calls can run in parallel, so a check "passed" before the change had landed.
  • Offer only what was asked.I once added an option nobody requested. Now the rule: restate an ambiguous phrase before building from it.

About

An operations analyst who builds agents.

At work I support a product R&D team's testing operations: trackers, reporting and data. A lot of that is answering the same kinds of questions from several systems. So I built an agent for it, and then learned the hard parts. It has to be right, it has to say when it can't be, and someone has to notice when it gets worse.

I'm moving from analytics into AI engineering. That is a transition, not a rebrand. The projects here are what I built to make it, and I've tried to be exact about what each one does and doesn't show.
