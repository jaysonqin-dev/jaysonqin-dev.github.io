How I train my agent

My own agent has about 130 rules, each from a real correction.

I use a personal AI analyst every day. It doesn't improve because I write a longer prompt. It improves because every correction goes through a quality bar, and only the ones that generalize become rules.

How it works Try the triage yourself
  • Verify a metric against the source's definition before encoding it.A rule written from a verbal description would have subtracted a quantity twice. The live agent caught it by reading the data model's glossary.
  • Don't batch an edit and the command that tests it.Independent tool calls can run in parallel, so a check "passed" before the change had landed.
  • Offer only what was asked.I once added an option nobody requested. Now the rule: restate an ambiguous phrase before building from it.

About

An operations analyst who builds agents.

At work I support a product R&D team's testing operations: trackers, reporting and data. A lot of that is answering the same kinds of questions from several systems. So I built agents for it: first one for myself, then one for the team's leaders, who now use it. Then I learned the hard parts. An agent has to be right, it has to say when it can't be, and someone has to notice when it gets worse.

I'm moving from analytics into AI engineering. That is a transition, not a rebrand. The projects here are what I built to make it, and I've tried to be exact about what each one does and doesn't show.
